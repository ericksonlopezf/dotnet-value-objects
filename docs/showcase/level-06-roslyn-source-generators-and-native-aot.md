## 1. Incremental Source Generation with `[ValueObject]`

Decorating custom value objects with `[ValueObject]` synthesizes `IParsable<TSelf>` and `ISpanParsable<TSelf>` implementations at compile time:

```csharp
using EricksonLopez.ValueObjects;

[ValueObject]
public sealed record class DepartmentCode : StringValueObject<DepartmentCode>
{
    private DepartmentCode(string value) : base(value) { }

    public static Result<DepartmentCode> Create(string? value)
    {
        if (string.IsNullOrWhiteSpace(value) || value.Length < 2)
            return Error.Validation("DeptCode.Invalid", "Invalid department code.");

        return new DepartmentCode(value.Trim().ToUpperInvariant());
    }
}
```

The generator emits:
```csharp
// <auto-generated/>
partial record class DepartmentCode : IParsable<DepartmentCode>, ISpanParsable<DepartmentCode>
{
    public static DepartmentCode Parse(string s, IFormatProvider? provider = null) => ...;
    public static bool TryParse(string? s, IFormatProvider? provider, out DepartmentCode result) => ...;
}
```

## 2. Roslyn Diagnostic Enforcement

During build time, Roslyn analyzers intercept architectural rule violations:
- `ELVO001`: Rejects `public` constructors.
- `ELVO002`: Rejects missing `public static Result<T> Create` methods.
- `ELVO003`: Rejects mutable `set;` properties.

---

## 3. NativeAOT Trimming Compatibility

100% of methods and converters avoid `System.Reflection`, `MakeGenericType`, or dynamic code generation. This guarantees seamless execution in trimmed NativeAOT binaries with zero `IL2026` or `IL3050` trimming warnings.
