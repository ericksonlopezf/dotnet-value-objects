# Support Guidelines

Thank you for using `EricksonLopez.ValueObjects`! Below are the recommended channels and resources for obtaining help and reporting issues.

---

## 1. Documentation & Architecture Guides

Before filing an issue, please consult the official documentation in `/docs/`:

- [Architectural Blueprint](docs/architecture.md): Strategic design, type hierarchies, and performance model.
- [Corporate Value Objects Design](docs/corporate-value-objects-design.md): Invariant catalog and Fowler Money arithmetic.
- [Fiscal Architecture Specification](docs/fiscal-architecture-specification.md): Complete regulatory guide for LATAM fiscal packages (DO, MX, AR, CL, CO, PE).
- [NuGet Package Catalog](docs/nuget-packages.md): Target frameworks, dependencies, and public API surface.
- [Architecture Decision Records (ADRs)](docs/adr/README.md): Formal design decisions and rejections.
- [Sample Projects](samples/EricksonLopez.ValueObjects.Samples/): 11 progressive learning levels from conceptual overview to enterprise domain services.

---

## 2. Getting Help & Asking Questions

- **GitHub Discussions**: For general questions, design discussions, and usage questions, please open a thread in [GitHub Discussions](https://github.com/ericksonlopezf/dotnet-value-objects/discussions).
- **GitHub Issues**: If you have found a reproducible bug or would like to propose a concrete feature, open an issue using the appropriate template in [GitHub Issues](https://github.com/ericksonlopezf/dotnet-value-objects/issues).
- **Direct Support Email**: Reach the core maintainer at [ericksonlopezf@gmail.com](mailto:ericksonlopezf@gmail.com).

---

## 3. Reporting Security Vulnerabilities

For security-sensitive issues, please follow the confidential disclosure instructions in [SECURITY.md](SECURITY.md). Do not file public issues for security vulnerabilities.
